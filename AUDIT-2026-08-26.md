## 4. Findings — severity ordered

### F1 (critical) Supervisor is not wired to checkpoint/resume
- `supervisor.py:196` spawns `harness.py run-one`. `run-one` (handlers.py:70) does
  **not** call `resume_in_flight`, and no `--continue` is passed anywhere.
- The cycle decision (`supervisor.py:188-196`) counts `pending` only. With a task
  stuck in `active/` it evaluates `pending=0` and runs **autonomous generation**
  instead of finishing the in-flight task.
- `cmd_run_task_loop` docstring (handlers.py:92-96) states the supervisor calls it
  with `--continue`. It does not. Stale docstring.
- Net effect: slices 1-3 of the resume feature are unreachable in the self-driving
  loop; they work only when a human types the command.

### F2 (critical) `claimed/` leak — 7 tasks currently invisible
- `cmd_run` (handlers.py:44-56) calls `fetch_pending(claim=True)`, which moves every
  `pending/*.md` into `queue/claimed/`, then processes them in a Python loop with no
  requeue of the remainder. `_requeue_claimed` exists but is only used by `run-one`
  and `run-task-loop`.
- Live evidence: `queue/claimed/` holds `003-keep-rejected-features...`,
  `004-model-refresh`, `005-stats-for-rejected-auto-ideas...`,
  `007-sandbox-for-harness...`, `008-coding-standards`, `auto-3-...`, `auto-4-...`.
- `cmd_status` lists pending/active/done/failed/parked/review — **not** `claimed/`, so
  these are invisible. `--continue` does not scan `claimed/` either.

### F3 (critical) All supervised harness output is discarded
- `ChildTracker.spawn` (`supervisor.py:113-119`) uses
  `stdout=subprocess.DEVNULL, stderr=subprocess.DEVNULL`.
- `composition._log` / `handlers._log` only `print()`. Nothing writes
  `work/logs/harness.log` (README claims it does); `cfg.logs_dir` is only `mkdir`'d.
- Result: in supervised mode every verdict line, heartbeat, warning and traceback is
  lost. Only the supervisor's own one-line-per-event log survives.

### F4 (high) `task.json` `status` is never updated
- `status` is written once at `intake()` (task_lifecycle.py:165) and never rewritten
  by `park()` / `fail()` / `complete()` — they move the directory only.
- Live evidence: `queue/parked/001-interrupt-handling/task.json` contains
  `"status": "active"`.
- Directory location is the only truth; `TaskStatus` is effectively decorative.

### F5 (high) `external/pi_cli.py` hang risks
- `stderr=subprocess.PIPE` (pi_cli.py:88) is never drained until after the stdout
  loop ends (pi_cli.py:117). A chatty stderr fills the OS pipe -> child blocks -> deadlock.
- The `HARD_TIMEOUT_S` deadline (pi_cli.py:86) is checked only inside
  `for line in proc.stdout:` — a blocked read yields no line, so a silent/hung
  session never times out. There is no wall-clock watchdog.
- `_extract_verdict` (pi_cli.py:164) regex is `[a-z_]+` — an uppercase
  `VERDICT: DONE` parses as `unknown`; the appended `[stderr]` block
  (pi_cli.py:139) is part of the parsed text, so stderr content can yield a verdict.
- `unknown` verdict is treated as failure by stages, which drives retry/park loops.

### F6 (high) `external/git_cli.py` revert path is broken
- `_has()` (git_cli.py:22-25) probes `refs/heads/<ref>`. `LAST_GOOD_TAG` is a **tag**,
  so `_revert_to_last_good` (git_cli.py:101-108) never finds it and always falls back
  to `git reset --hard HEAD~1`. Verified: `refs/heads/pi/last-good` rc=1,
  `refs/tags/pi/last-good` rc=0.
- `merge_to_trunk` (git_cli.py:56-58): a failing `merge --squash` raises from `_git`
  with no `merge --abort` / worktree cleanup, leaving the repo mid-merge.
- Circuit breaker (`supervisor.py:180-186`) runs `git reset --hard pi/last-good` over a
  possibly dirty tree. The working tree is dirty right now (`config.json`, `README.md`,
  deleted `supervisor.sh`) — a breaker event destroys them.

### F7 (high) `verify_harness` is only valid for the harness repo itself
- `verify_harness` (git_cli.py:75-98) runs `import harness...` and
  `python harness.py status` with `cwd=workdir`. For any other repo the import fails,
  so the gate can never pass and every merge is reverted + the task parked.
- Coupled with `resolve_workdir` (task_lifecycle.py:225-238), which regex-scrapes
  absolute paths out of `original.md` and falls back to the **task dir**, a task that
  doesn't name a repo gets `ensure_branch` -> `git init` inside `queue/active/<id>/`.
  Confirmed live: `queue/active/002-pipeline-checkpoint-and-resume/.git` exists with a
  single "harness: initial commit" and the sessions ran against that scratch repo.
- Consequence: session output files (`.pi-session-*.out`) land in the workdir, and the
  merge gate does `reset --hard` inside the queue tree.

### F8 (high) Resume granularity is too coarse
- `slices` is a single checkpointable stage (`CheckpointStage.SLICES`). A crash after
  slice 3 of 5 re-runs slices 1-3. No per-slice checkpoint.
- `holistic` is deliberately never checkpointed. A crash between the squash-merge and
  `complete()` resumes into `stage_holistic`, where `merge --squash pi/<id>` now fails
  because `merge_to_trunk` deleted the branch (git_cli.py:72) -> parks.

### F9 (medium) Standards adoption is half done
- `Verdict` and `Stage` (core/enums.py) have **zero call sites**. `pipeline.py` has 12
  raw `verdict == "..."` comparisons.
- `Stage` values don't match the strings actually used in stats: enum says `implement`,
  `tech_review`, `holistic_review`, `slice_fit`; the code passes `slice_implement`,
  `tech_review`/`func_review` (built via f-string), `holistic`, `slice_check`,
  `slice_fix`, `spec_assess_ornith`. The enum is actively wrong.
- `Verdict` has no `KICKOUT`, which `_outcome()` (session.py:119) treats as valid.
- Unused imports: `ensure_branch` (task_lifecycle.py:19), `shutil` + `CheckpointStage`
  (resume.py:9,13), `build` + `CONFIG_PATH` (harness.py:20,25), `re`/`shutil` in
  pipeline partially used.
- `resume._plan_stages()` (resume.py:24-27) mixes `CheckpointStage` members with the
  bare string `HOLISTIC` in one tuple.
- `_log` is duplicated in composition.py and handlers.py.

### F10 (medium) Config / budget semantics muddled

- Measured with the current config: 128k models -> prompt says **51k**;

- Log line `budget={budget}k ctx={...}k` (session.py:63-64) prints raw token counts

- README "Token budget (default 60k)" vs `load()` default `100_000` (config.py:80) —
  and the README/config edits are uncommitted.

## 5. Suggested order of work

1. Supervisor: `run-task-loop --continue`, count in-flight (and `claimed/`) in the
   cycle decision, send child output to a real log instead of `DEVNULL`.
2. `claimed/`: requeue stale claims at startup; surface `claimed/` in `status`.
3. `pi_cli`: drain stderr on a thread, wall-clock watchdog that kills regardless of
   output, case-insensitive verdict regex, exclude stderr from verdict parsing.
4. `git_cli`: `refs/tags/` lookup for last-good, `merge --abort` on failure,
   repo-aware `verify_harness`, refuse `reset --hard` on a dirty tree.
5. State truthfulness: write `status` on park/fail/complete; record `workdir` in
   `task.json` at intake so resume never re-derives it by regex.
6. Per-slice checkpointing + a merge/complete checkpoint.
7. Adopt `Verdict`/`Stage` at the call sites and correct their values — or delete them.
8. Boundary tests (pi_cli parse/timeout/crash, git_cli merge/revert/verify, handlers)
   plus a CI job running unittest + the gate.
9. Fix budget semantics and log units; commit the pending `config.json` / `README.md` /
   `supervisor.sh` changes; re-sync README and the refactor docs.
10. Queue hygiene: normalize the 002 `task.json`, clear `claimed/`, truncate/rotate
    `supervisor.log`.
