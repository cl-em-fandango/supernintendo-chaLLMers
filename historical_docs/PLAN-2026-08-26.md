## How to run a card (agent contract)

1. Read this file's **Gate**, **Rules**, and **Open decisions**. Then read your card.
2. Read only the card's **Read first** files. Do not spelunk the repo.
3. Make the change. Run the card's **Verify** block *and* the global Gate.
4. Commit with the card's message. Advance `pi/last-good` only if the card is tagged `[tag]`.
5. If the Gate fails and you cannot fix it inside ~15 minutes: **STOP**, write
   `plan-2026-08-26/HANDOVER-<card-id>.md` (what you changed, what fails, exact error,
   what you would try next) and exit. Do not paper over a failure.
6. **Token stop-rule:** if your context is anywhere near 80k tokens, stop implementing,
   write the HANDOVER file, and exit. Half-finished code with a good handover beats
   finished code and a corrupted tree.

## Rules that bind every card (from CODING_STANDARDS.md)

- `external/` owns **all** subprocess. `cli/` parses+dispatches only. `workflow/` composes.
  `harness.py`/`composition.py` wire only. Direction: `cli → workflow → core → external`.
- No new magic strings: discrete state is an `enum` member inside our code; raw strings
  only at the process edges (the `VERDICT:` line, a git ref).
- No `dict`/tuple for meaningful state — a named dataclass.
- Behavior-preserving unless the card says the behavior is wrong and must change.
- Never run the supervisor, never start a pi session, and never `git reset --hard` as
  part of implementing a card. Tests must use `tmp_path`-style temp repos and fake
  executables on `PATH`, never `/home/donald/work/queue` or the real harness repo.
- **`AGENTS.MD` says "never write to `/home/donald/work/{queue,stats,logs}`". Narrow exception,
  and nothing wider:** a card's own Verify block may let the harness *append* to
  `work/logs/harness.log`/`supervisor.log` and may write a new report file there (T07, T25), because
  that write *is* the acceptance criterion. The exception covers appends only. No card may delete,
  truncate, move or rewrite a pre-existing file under `/home/donald/work/`, and no card may move a
  queue file (D4). Concretely: T02's one-time truncation of `supervisor.log` and every real-queue
  mutation are **human-performed operator steps** — the card prints the command, the human runs it.
- Docstrings, README and handover files must not name a card that does not exist. Card ids run
  T01–T73; if a card needs behaviour owned by a non-existent card, it is a plan gap — stop and
  record it, do not invent an id.
- A Verify block may not contain an assertion that cannot fail (`... or True`, a duplicated
  `hasattr(a) or hasattr(a)`, a chained `x is False`). Delete such lines and assert the real thing.
